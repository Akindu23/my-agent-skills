# Commit message

Invoke with **`/commit-msg`**. Stage is the source of truth. History supplies *style*. The subject you pick is the commit, **without the attributions**.

## 1. Gather

Run in parallel:

```bash
git status
git diff --cached
git log -20 --pretty=format:%s
```

**Done when**: staged paths and the last ~20 subjects are in context, or you have stopped because there is nothing staged (tell the user to stage first; do not stage for them).

Skip secrets (`.env`, credentials, keys). If a staged path looks secret, stop and name the path.

## 2. Draft

Write **3–5 one-liners**. Each option is a distinct framing of the same staged change (why, scope, or verb), not a synonym of another.

Match *style* from those subjects: conventional vs freeform, tense, capitalization, punctuation. Empty history → imperative subject, no prefix invented.

Every option is a **one-liner**: a single subject. The committed text is only that line.

**Without the attributions.** No `Co-authored-by`, `Signed-off-by`, `Made-with`, `Generated by`, 🤖, or any other trailer or byline — including ones this repo's history already has. Match *style* from the subjects, not the trailers.

**Done when**: every option is a one-liner in this repo's *style*, without the attributions.

## 3. Pick

Use **`AskQuestion`** with one question; each option's label is the one-liner itself. If **`AskQuestion`** is missing, list the same options in chat and wait.

**Done when**: the user has chosen one line (including a line they typed).

## 4. Commit

```bash
git commit -m "$(cat <<'EOF'
the chosen one-liner

EOF
)"
git status
```

No amend, no hook skip, no push, no `git config` edits.

**Done when**: `git status` shows the staged files in that commit, HEAD is exactly the chosen one-liner, and `git log -1` has no attributions.
