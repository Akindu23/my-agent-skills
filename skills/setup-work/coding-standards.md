# Coding standards

Reviewer-owned. `/code-review` applies every rule under **Rules**. Implementers skip this file.

A line belongs in **Rules** when it is a convention of this repository that should bind future diffs. Prefer a one-line rule; point at a doc under `docs/` when the rule needs examples.

Tooling (`eslint`, `tsc`, tests) stays in those configs. Skill-owned discipline stays in those skills (`karpathy-guidelines`, `yagni`, `codebase-design`). Task-scoped recon stays in the plan that used it.
